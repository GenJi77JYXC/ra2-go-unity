## 胜负条件

学习计划没有规定判负标准(只提到房间有 `Waiting/Playing/Finished` 三态),
这里按原版提供三种,由创建房间的人选择:

| 条件 | 判负标准 | 对应原版 |
|---|---|---|
| `buildings` | 所有建筑被摧毁(单位还在也算输) | RA2 默认 |
| `conyard` | 主基地被摧毁 | Short Game |
| `annihilation` | 建筑和单位全灭 | 全灭规则 |

实现见 [server/game/victory.go](server/game/victory.go)。

## 经济:矿脉、矿柱、采矿车

收入全部靠采:地图上有矿区,中间立着**矿柱**(中立设施,不断在周围把采空的
矿慢慢长回来,由内向外)。造 `OreRefinery` 会附送一辆采矿车,它自己往返于
矿区和矿场之间,卸货才进账——**没有任何被动收入**,所以开局 5000 块怎么花
是个真的决策。

精炼厂本身不生产任何东西,**追加的采矿车出自战车工厂**(和原版一致),
和坦克共用同一条载具队列——所以每多一辆矿车就是少一辆坦克。

矿量每 tick 都在变,而 `GameMap` 是"建一次、永不修改、可无锁跨 goroutine 读"
的。所以沿用避让那套切分:地图只记**哪些格是矿区**(静态),剩余量放
`World.ore`(动态)。

采矿车是第一个**自己有行为**的单位,但它的状态机不直接操纵坐标——每个状态
只设一个 `Goal` 然后等它走到,所以被挡住、让路、绕行全部继承自下面那套避让
机制。实现见 [server/game/harvest.go](server/game/harvest.go)。

## AI 对手

创建房间时勾选 **vs AI**,一个人 Ready 就开局,另一个座位交给电脑。

AI 每秒看一次棋盘(`assess`)、重排目标(`reassessGoals`)、在每条资源线上
各执行一个目标(`executeGoals`)。它**不直接改 `World`,只产出 `Command`**,
和人类玩家走同一个 `HandleCommand`——所以所有权校验、预置条件、扣款全都照常
生效,AI 没有作弊的路径。

目标优先级每秒从棋盘**从零重算**,不做增量更新。因此"矿场被拆自动重建"和
"电力不足自动补电厂"不需要任何专门规则:建筑没了,下一秒对应目标的优先级
自然就回到最高。

AI 也会补采矿车和卖楼,但都有节制:采矿车只在**第一波攻势成型之后**才排到
坦克前面(否则 600 块花在经济上会把第一波推迟整整一分钟);卖楼只卖
**卖掉之后电力仍然不为负**的多余电厂——这个限制正是防止"卖了又造"死循环的
关键。

学习计划提醒过 `Goal` 只有 pending/active/completed 三态、没有 failed,地图
拥挤时会卡死。这里给目标加了失败计数和**递增退避**(5/10/15…秒,上限 30),
退避期间该资源线让给下一优先级的目标。

实现见 [server/game/ai.go](server/game/ai.go)。

## 出售建筑

选中自己的建筑,面板底部有出售按钮,退还**造价的 50%**(原版的比例)。
要点两次确认——半价是真的损失,不该被误触。

没有任何建筑豁免。把基地或所有建筑卖光是允许的,并且会按 `buildings` 规则
直接判负——这是原版行为,想认输就该能认。预置的基地模板造价为 0,所以卖它
退 0,纯粹是个投降键。

## 单位避让与占地

单位按格占地:要离开当前格,得先**预约**下一格,过渡期间同时占住两格,
所以谁也钻不进别人正在跨越的缝里。建筑同样占地,寻路会绕开而不是穿过去。

被挡住之后是分级处理的,直接重新寻路会让单位互相蹭来蹭去:

| 情况 | 处理 |
|---|---|
| 挡住不到 0.5 秒 | 原地等——大多数堵塞自己就散了 |
| 超过 0.5 秒 | 重新寻路,这次把其他单位占的格也算障碍 |
| 绕不开,挡路的是静止单位 | 让对方挪一格;它挪完会停 1 秒,不然刚让开就走回来 |
| 正面对堵 | 按单位 ID 决定谁让,保证只有一个人动 |
| 挡住满 3 秒 | 放弃这次指令 |

单位记着自己的最终目的地(`Goal`),所以让完路会自己接着走原来的行程。
一个例外:**只检查要进入的格,不检查当前所在的格**——建筑可以盖在单位头上,
被盖住的单位必须还能走出来。

实现见 [server/game/occupancy.go](server/game/occupancy.go),
测试见 [server/game/movement_test.go](server/game/movement_test.go)。

## 快速开始

```bash
cd server
go run .
```

Unity 端从 **Menu 场景**启动(游戏场景需要大厅创建的持久连接对象,不能直接 Play)。
双人对战需要两个客户端,可以打包一个 exe 再配合编辑器 Play。

只验证服务端协议的话,不必开 Unity:

```bash
# 连上后手动发大厅/游戏指令，例如 {"type":"listRooms"}
websocat ws://localhost:8080/ws
```

Unity 工程见 `client/README.md`。
